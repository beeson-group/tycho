# The TyCHO documentation site

The site is built by Sphinx, the Python documentation generator, with MyST-Parser, which lets Sphinx read Markdown, and the pydata-sphinx-theme, which gives the pages their layout. It is hosted by [Read the Docs](https://pytycho.readthedocs.io/), which reads `.readthedocs.yaml` at the repository root. Read the Docs builds three kinds of version.

- Every pull request gets a preview, linked from the checks of the pull request.
- Every push to `main` is built as `latest`.
- The highest release tag is built as `stable`.

A warning fails the build there, as it does locally.

## Build locally

From the repository root, `uvx nox -s docs` builds the site into `docs/_build/html`, and `uvx nox -s docs -- --serve` serves it on a local web server and rebuilds it on every change. Both commands install `docs/requirements.txt`, i.e. the versions that Read the Docs builds with. These versions require Python 3.12 or later, as Sphinx 9.1 does. Without nox, the command below builds the site.

```sh
uv run --python 3.14 --group docs sphinx-build -W --keep-going docs docs/_build/html
```

The commands below build the site in a separate virtual environment, with the versions that the site was checked with.

```sh
uv venv docs/_build/venv --python 3.14
uv pip install --python docs/_build/venv/bin/python -r docs/requirements.txt -e .
docs/_build/venv/bin/sphinx-build -W --keep-going docs docs/_build/html
```

Open `docs/_build/html/index.html` in a browser to read the result. The flag `-W` turns every warning into an error, and the site builds without warnings. The build imports pytycho from `src/` to read its version and its docstrings, hence it requires NumPy but not the built runtime, which only the page writer uses. The intersphinx inventories of Python and NumPy, i.e. the indexes that let the site link a name to its page in the documentation of Python or NumPy, are fetched over the network.

## What comes from elsewhere

The pages read the files below where they live in the repository, meaning that the site follows them without copies and always shows their current text.

- `spec.md` includes `spec/tycho-scene.md`, `schema.md` includes `spec/scene.schema.json`, and `conformance.md` includes `spec/conformance/README.md`.
- `agents.md` includes `skills/tycho/SKILL.md`.
- `changelog.md` includes `CHANGELOG.md` when it exists, and shows where the release notes are when it does not.
- `api/python.md` is generated by autodoc, the Sphinx extension that reads docstrings, from `src/pytycho`. Since `api/javascript.md` is written by hand from `web/src/index.ts` and `web/src/runtime/element.ts`, update it when these two files change.

## The `_extra` directory

`_extra/` is copied unchanged to the root of the site, and the `.gitignore` at the repository root ignores it, since it holds only build outputs.

- `conf.py` stages `spec/scene.schema.json` and `spec/tycho-scene.md` into `_extra/schema/<format>/` on every build, where `<format>` is the version of the scene format. Thus the schema is published at `schema/0.2/scene.schema.json`, the URL that its `$id` gives, i.e. the URL that identifies the schema.
- The example pages are not kept in git. On Read the Docs, `conf.py` downloads them into `_extra/examples/` from the download links of the latest GitHub Release, which work without a token or an API call. In the gallery, `broucke.html` is reached through a link that shows its size, under the poster `broucke.png` when there is one. Without these pages, e.g. before the first release, the gallery shows where the pages are, and the build still passes.

To see the gallery locally, set `TYCHO_DOCS_EXAMPLES=1` for the build, which then downloads the pages of the latest release as Read the Docs does. Alternatively, build the page from its input (see the quickstart) and copy it in with the commands below.

```sh
mkdir -p docs/_extra/examples
cp examples/broucke/broucke.html examples/broucke/broucke.png docs/_extra/examples/
```

A poster is a PNG (Portable Network Graphics) image named after its page, e.g. `broucke.png`, which the gallery shows as a still of the page. It can be a frame of the video export of the page, and `web/scripts/poster.mjs` takes one from a built page, as `CONTRIBUTING.md` describes in its release steps.
