# Writing a TyCHO scene

TyCHO draws what it is given. A _scene_ is the description of one animated page, which pytycho writes as two files, the scene document `scene.tys` and the data container `data.tyd`. A scene consists of NumPy arrays and of declarations of track sets with per-sample channels, bodies, a tree of frames, variables, one clock, views with layers, panels, controls, and readouts. The section "How the pieces fit" below explains each of these declarations. The runtime, i.e. the browser code that pytycho inlines into the page, rotates, scales, translates, and blends linearly between two stored samples. It never integrates, never creates a sample by interpolation, and does not hold a formula of any dynamical model. Every position and every channel value therefore comes from the caller, i.e. from the script that builds the scene.

## The minimal scene

The script below writes a page that shows one closed loop, stored in a rotating frame, in two panels side by side. The panel `p1` draws the loop in the rotating frame, and the panel `p2` draws it in an inertial frame, against which the rotating frame turns by the stored channel `angle`.

```python
import numpy as np
import pytycho as ty

scene = ty.Scene(title="a rotating loop")
rotating = scene.frame("rotating", axes=("x", "y", "z"))
scene.frame("inertial", parent=rotating, rotation=ty.rotation("z", ty.channel("angle")))

loop = scene.track_set("loop", frame=rotating, periodic=True)
angle = np.linspace(0.0, 2.0 * np.pi, 400)
loop.add(np.column_stack([np.cos(angle), 0.5 * np.sin(angle)]), channels={"angle": angle})

frame = scene.choice("frame", ["rotating", "inertial"], scope="panel")
scene.clock(channels=["angle", "@index"], steps=200)
layers = [ty.track(loop), ty.track(loop, 0, trail=0.3, head=True, width=2.0), ty.axes()]
scene.view("main", frame=frame, driver=ty.driver(loop, 0), layers=layers)
scene.panel("p1", "main", {frame: "rotating"})
scene.panel("p2", "main", {frame: "inertial"})
scene.tabs(frame, label="frame")
scene.transport()
scene.write_html("loop.html")
```

A builder is any call that declares a piece of the scene, e.g. `scene.frame`, `loop.add`, or `ty.track`. Every builder checks its arguments at the call and raises `SceneError` with the rule it breaks. The methods `to_document()` and `write()` then check the whole scene, for every value the variables can take, and report all failures at once. This second check covers the cross-references between the pieces and the rules that depend on the values of the variables. The method `write_html` makes it as well, since it builds the document through `to_document()`. Each line of the report starts with the rule number from [`spec/tycho-scene.md`](https://github.com/beeson-group/tycho/blob/main/spec/tycho-scene.md), e.g. `F5` or `2.7`. Read the rule, fix the scene, and never work around a check by editing the document.

## How the pieces fit

- A _track set_ holds tracks that share a frame and a meaning, e.g. a family, a manifold, or one transfer. A track is one trajectory, i.e. a sequence of samples, and a sample is one stored point of the trajectory with the numbers stored for it. The method `scene.track_set(id, frame=, periodic=)` declares a set. Its method `add(positions, channels=, parameters=)` takes one track as `(m, 2)` or `(m, 3)` positions, channels as one value per sample, and parameters as one number per track. In these shapes `m` is the number of samples of the track, and a position of two columns is planar, with `z = 0`. A channel is a quantity that changes along the track, e.g. the time, and a parameter is a quantity of the whole track, e.g. its period or its eccentricity. Every track of a set gives the same names, because the writer stores each channel and each parameter of a set as one array over all its tracks. With `periodic=True`, the last sample is the closing sample, one period after the first, i.e. the first sample again, reached one period later. The advance of a channel over one period is then its value at the last sample minus its value at the first, e.g. the period itself for a time channel.
- A _frame_ is a coordinate frame, e.g. the rotating frame of the restricted three-body problem or an inertial frame, declared with `scene.frame(id, parent=, origin=, rotation=, scale=)`. The frames of a scene form a tree, whose root is the one frame without a parent. A frame is defined against its parent by an origin (three numbers or attributes, or a body), a rotation about an axis, and a scale. The angle of the rotation and the scale may each read a _channel_ of the drawn sample (`ty.channel("true_anomaly")`) or an _attribute_ of the drawn set (`ty.attr("mu")`, with `1 - ty.attr("mu")` allowed), and an origin may read an attribute but not a channel (rule F2). The call `ty.rotation("z", angle)` gives a rotation by `angle` radians about the axis z. An attribute is one number for a whole track set, given in `attrs=` of `scene.track_set`, e.g. the mass ratio `mu`. An expression such as `1 - ty.attr("mu")` stands for a factor times the attribute plus an offset. One attribute thus places both the primary at `-mu` and the secondary at `1 - mu`. A set drawn in a frame must carry every channel and attribute on the path, which is rule F5, and the writer reports which one is missing. An edge is the link from a parent frame to a child frame. The path is the chain of edges from the frame of the set to the frame in which it is drawn. Every edge on the path is evaluated with the channels of the drawn sample and the attributes of its set.
- A _body_ is a point in a frame at three numbers or attributes, declared with `scene.body(id, frame=, position=)`, e.g. the primary at `[-ty.attr("mu"), 0.0, 0.0]`. It takes the context of the view's _driver_, the one track a panel follows. The context is the set, the track, and the sample from which a channel or an attribute is read. A body does not have samples, hence it reads its channels at the samples of the driver (rule F4). A body drawn in a frame that rotates by a channel thus moves with the samples of the driver.
- A _variable_ is a piece of state that a person viewing the page can change through a control, and a scene has three kinds of variables. A `selector` holds a parameter value and resolves to the nearest member of each set, or holds a track index under `by="index"`. A member is one track of a set, and the nearest member is the track whose value of the selector's parameter lies closest to the value of the selector. A `choice` holds one of its strings, e.g. the id of a frame, and a `toggle` holds a boolean, e.g. whether a layer is shown. The methods `scene.selector(id, parameter=)`, `scene.choice(id, values, scope=)`, and `scene.toggle(id)` declare them. Under the default `scope="scene"`, the page holds one value of the variable. Under `scope="panel"`, every panel keeps a separate value, which is how one view serves five frames. The Broucke example, for instance, shows one view in five panels, each with a different value of a panel-scoped choice of frame.
- The _clock_ is the animation time. It is shared by every panel, so that all panels move together, and `scene.clock(mode, channels=, steps=)` declares it. Its `steps` is the number of animation frames, i.e. drawn pictures, in one loop of the animation. The first of its `channels` is the active channel at the start, i.e. the clock channel whose value is read as the time, and the transport control switches among them. In `fraction` mode, one loop takes every track from the first to the last value of the active channel on the track, which keeps members of different periods in phase. In `value` mode (`range=`) the shared channel value drives every track, for a common epoch. In this mode the value of the channel runs through the interval `range` over one loop, and every track is shown at the point where its channel takes this value. Every clock channel is strictly monotone along each track, i.e. it only increases or only decreases, so that each of its values occurs once on a track (rule T3). The channel `@index` is the stored sample index. A set drawn with a trail, a head, or a grow must carry every clock channel. A set drawn whole with `reveal="none"`, on which a reading is not taken and which is not a driver, does not have to carry any (rule C5). A grow is a layer with `reveal="grow"`, which draws each track from its start up to the moving point. A set is drawn whole by a layer with the default `reveal="none"` and without a head (rule C5).
- A `fraction` clock can run several _laps_ per loop, where a lap is one traversal of a periodic track from its first sample to its closing sample. The call `scene.clock("fraction", channels=[...], steps=480 * 9, laps=9)` makes one loop run every periodic track 9 times, and lap `j` is read with every channel raised by `j` periods. A channel raised by `j` periods has each of its values increased by `j` times the advance of the channel over one period. An orbit drawn in a frame that turns by the time therefore keeps turning instead of jumping back (rule C6). With a single lap, the angle of such a frame returns to its starting value at the start of every loop. A trail fraction is then a fraction of the whole loop, and a readout reads the current lap of the driver. The writer rejects laps on a `value` clock, and on a set that is not periodic when a trail, a head, a grow, or the driver reads this set. The reason is that only a periodic set defines what its next lap is.
- A _view_ is a template for a panel, i.e. for one picture on the page, declared with `scene.view(id, frame=, driver=, layers=, camera=)`. It combines a frame (or a choice of frames), a driver, a camera, and layers. The frame is the display frame, in which everything is drawn. The driver, given by `ty.driver(sets, member)`, is the track that the animation follows, and the bodies and the readouts of the view take their context from it. The camera is a plane camera, `{"kind": "plane"}`, which draws a flat picture of one coordinate plane, or an orbit camera, `{"kind": "orbit"}`, which draws a three-dimensional picture that can be turned. Under a plane camera with `"aspect": "free"`, the two axes are scaled separately for a diagram such as a residual against an iteration count, and under the default, `"equal"`, the shape of an orbit is kept. Each layer draws one thing, and the layers are `ty.track(sets, members, reveal=, trail=, taper=, head=, context=, color=, opacity=, width=, highlight=)`, `ty.body(body, trail=, size=)`, `ty.axes(span=)`, and `ty.grid(labels=)`. The argument `sets` is a set, an id, or `ty.sets(family=choice_var, branch="periapsis")`, a tags query that must not match more than one set for any value of its variables, while a query without a match leaves the layer empty (rule V2). The tags of a set are the strings given in `tags=` of `scene.track_set`, and a tags query matches every set whose tags contain all the pairs of the query. A value of the query may be a choice variable, e.g. `choice_var` above, and the query then follows the value of the choice.
- The _layer options_ set which members a layer draws and how it draws them.
  - The option `members` is `"all"`, a track index, a selector, or `ty.every(40)`. The call `ty.every(n)` is the `{"count": n}` reference to the tracks `0, s, 2s, ...` and the last track of a set of `N` tracks, with `s = floor(N / n + 0.5)`. The call `ty.every(40)` thus spreads about 40 members over the set as a context. A context here is a sparse selection of the set, i.e. one that keeps every `s`-th track, and the step is 1 when `n` is at least `N` (rule V3). A driver's member is never a count (rule V3), since the driver must resolve to one track.
  - The option `color=` is `"#rrggbb"` or `{"parameter": "eccentricity", "colormap": "viridis"}`. The first is a fixed color, with two hexadecimal digits each for red, green, and blue. The second is a colormap over a parameter, which gives each track the color of its parameter value, and the colormap names are `viridis`, `plasma`, `cividis`, `blues`, and `reds`. The colormap can be keyed on a choice, as in `{"var": frame, "map": {"rotating": "blues", "inertial": "plasma"}}`, e.g. to give each display frame a separate colormap. The map then holds one name for every value of the choice and does not hold any other key, and the value of the panel picks the name (section 2.7).
  - The option `highlight={"var": e, "width": 2.5, "kernel": {"width": 0.05, "opacity": 0.55}}` draws the member that the selector picks. In this example `e` is a selector. The highlighted member is drawn with the width of the highlight in CSS pixels (by default the width of the layer) and with its opacity (by default 1). The kernel also brightens the neighbors of this member, with a Gaussian falloff in the parameter of the selector. The kernel requires a selector by `nearest`, and it brings up a member at distance `d` in its parameter to opacity `max(o, a * exp(-(d / (w * extent))^2))`. In this formula, `w` and `a` are the width and the opacity of the kernel, `o` is the opacity of the layer, and `extent` is the range of the parameter over the set (section 2.7). The distance `d` is measured from the parameter value of the highlighted member, and the opacity of the layer stays the floor.
  - The options `trail=0.3, taper=(0, 0)` fade the width and the opacity from the head to `taper` times their values at the tail, and `taper` defaults to `(0.25, 0.35)`. A trail of 0.3 draws the last 0.3 of the loop behind the moving point, and a `trail` fraction implies `reveal="trail"`. The pair `taper` gives the fractions of the width and of the opacity that are left at the tail, hence `(0, 0)` fades the trail out completely.
  - The option `head=True` or `head={"color": "#f0e442", "size": 9}` draws the point at the reading, in the color of the layer, at a size that the runtime picks unless one is given (rule L3). The point at the reading is the current position of the moving point, and the size is in CSS pixels.
  - The option `context="driver"` transforms every sample of the layer into the display frame with the channels and attributes of the driver at its reading, rather than of the sample itself (rule L6). A grid of the rotating-pulsating frame, stored as a track set without channels and drawn whole, thus breathes and turns with this frame in the rotating and inertial frames. The driver's set must carry the channels of the frames, and the grid's set need not carry any.
  - The call `ty.axes(span="full")` runs the axes both ways through the origin, `span="positive"` draws the positive halves, and `ty.grid(labels=True)` numbers the grid. Under a plane camera, `span` and `labels` default to full and true. Only there do the axes get tick numbers and titles with the unit of the frame, e.g. `x̃ [DU]`, and only there does the grid get numbered lines that follow the view. The title of an axis is its label from `axes=` of `scene.frame`, followed by the `unit=` of the frame, which is DU (the distance unit) in this example. Under an orbit camera, `span` and `labels` default to positive and false.
- A _panel_ shows a view and holds a separate value of each panel-scoped variable. The call `scene.panel("p1", "main", {frame: "rotating"})` of the minimal scene adds the panel `p1`, which shows the view `main` with the choice `frame` set to `"rotating"`. The panels of a scene are laid out side by side in one row, unless `scene.layout` with `ty.split` arranges them otherwise.
- The _controls_ bind variables (`slider`, `tabs`, `toggle_control`) and the clock (`transport`). A control is a widget on the page that binds one variable, or the clock, to an input.
  - The method `scene.slider(selector, label=, domain=)` moves a selector by `nearest` from one parameter value to the next, over the sets that the set query `domain` matches.
  - The method `scene.tabs(choice, label=)` shows one tab per value of a choice.
  - The method `scene.toggle_control(toggle, label=)` switches a toggle.
  - The method `scene.transport()` adds play, pause, and the switch of the active clock channel. A scene without it is static, i.e. it shows the initial frame index and does not animate, apart from a kiosk page written by `write_html(path, kiosk=True)`, which plays at once.
- A _readout_ is text whose parts (e.g. `{"member": "eccentricity", "digits": 4}`, `ty.channel("time")`, or `1 - ty.attr("mu")`) are read through the driver of the panel. The method `scene.readout(place, *parts)` adds one, with `place` either `"panel"`, for a readout in each panel, or `"caption"`, for one readout below the panels. A caption readout is read through the first panel in layout order. A string part is shown as it is, a member part shows a parameter of the track of the driver, and `digits` is the number of significant digits.

## Thinning

Thinning drops stored samples of a set to make the page smaller. The method `track_set.thin(n, frames=[...])` keeps at most `n` stored samples per track at equal steps of arclength, measured in every frame listed, and never creates a sample. Each step between two consecutive samples counts with its largest length over the listed frames. Each of these lengths is taken relative to the extent of the set in its frame, i.e. the diagonal of the box that bounds every track of the set. Without `frames`, the arclength is measured in the frame of the set alone. Give it every frame the set will be drawn in, so that a flyby stays resolved where it is seen. A stretch that is short in one frame and long in another thus keeps its samples, because its long length counts.

The call `thin(tolerance=...)` runs Douglas-Peucker relative to the extent of the set, and `keep=` forces indices (e.g. thrust switches or epochs). The Douglas-Peucker algorithm adds samples until every dropped sample lies within a distance of `tolerance` times the extent from the segment between its kept neighbors, in every listed frame. The argument `keep` holds one list of indices per track, or a function that returns this list for a track index. Both endpoints of a track and every forced index are always kept, even when they number more than `n`. Thin after the last `add`, since `add` raises on a set that is already thinned.

## Where the channels come from

A frame edge is the link from a parent frame to a child frame, with its origin, rotation, and scale. Take every quantity that a frame edge reads from the library that computed the trajectory, per sample, and never from a formula in the script. Every number on screen then comes from this library, because the runtime only rotates, scales, translates, and blends what it is given. In the elliptic restricted three-body problem the independent variable is the true anomaly. Name the channel for it, and store the pulsation scale `rho` and the elapsed time per sample, as [`examples/broucke/build.py`](https://github.com/beeson-group/tycho/blob/main/examples/broucke/build.py) reads them from its input. The pulsation scale is the distance between the primary and the secondary, which scales the rotating-pulsating frame into the rotating frame. The elapsed time lets the clock run uniformly in time as well as in the true anomaly. In the circular restricted three-body problem in nondimensional units, the inertial angle is the time channel. The time unit is defined so that the rotating frame turns by one radian per time unit, hence the angle between the rotating frame and an inertial frame equals the time.

## Checking a scene

In the tests, the document from `scene.to_document()` validates against [`spec/scene.schema.json`](https://github.com/beeson-group/tycho/blob/main/spec/scene.schema.json), the JSON Schema of the scene document. The function `pytycho.evaluate(document, container, state, frame_index)` returns every drawn position for a frame index, the same answer that the browser draws. Use it to assert in a test that a scene draws what it should. Its `container` is the data container, e.g. the bytes from `scene.to_container()`, and its `state` is a state of the page, e.g. `document["initial"]`, the state in which the page opens. Both evaluators, this one and the one in the browser, pass the same conformance corpus in `spec/conformance/`, which is why their answers agree. The method `write_html` returns the size of every view and of the page, in bytes as stored. Three-component positions stored as float32 cost 12 bytes a sample before compression, planar ones 8, and each channel costs 4 bytes more.
