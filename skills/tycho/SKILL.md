# Writing a TyCHO scene

TyCHO draws what it is given. A _scene_ is the description of one animated page, which pytycho writes as two files, the scene document `scene.tys` and the data container `data.tyd`. A scene consists of NumPy arrays and of declarations of trajectory sets with per-sample channels, bodies, a tree of frames, inputs, one clock, panels with layers, controls, and readouts. The section "How the pieces fit" below explains each of these declarations. The runtime, i.e. the browser code that pytycho inlines into the page, rotates, scales, translates, and blends linearly between two stored samples. It never integrates, never creates a sample by interpolation, and does not hold a formula of any dynamical model. Every position and every channel value therefore comes from the caller, i.e. from the script that builds the scene.

## The minimal scene

The script below writes a page that shows one closed loop, stored in a rotating frame, in two panels side by side. The panel `p1` draws the loop in the rotating frame, and the panel `p2` draws it in an inertial frame, against which the rotating frame turns by the stored channel `angle`.

```python
import numpy as np
import pytycho as ty

scene = ty.Scene(title="a rotating loop")
rotating = scene.frame("rotating", axes=("x", "y", "z"))
scene.frame("inertial", parent=rotating, rotation=ty.rotation("z", ty.channel("angle")))

loop = scene.trajectory_set("loop", frame=rotating, periodic=True)
angle = np.linspace(0.0, 2.0 * np.pi, 400)
loop.add(np.column_stack([np.cos(angle), 0.5 * np.sin(angle)]), channels={"angle": angle})

frame = scene.choice("frame", ["rotating", "inertial"], scope="per_panel")
scene.clock(channels=["angle", "@index"], frame_count=200)
layers = [ty.trajectories(loop), ty.trajectories(loop, 0, trail=0.3, head=True, width=2.0), ty.axes()]
scene.panel("main", frame=frame, reference=ty.reference(loop, 0), layers=layers)
scene.show("p1", panel="main", inputs={frame: "rotating"})
scene.show("p2", panel="main", inputs={frame: "inertial"})
scene.tabs(frame, label="frame")
scene.playback()
scene.write_html("loop.html")
```

A builder is any call that declares a piece of the scene, e.g. `scene.frame`, `loop.add`, or `ty.trajectories`. Every builder checks its arguments at the call and raises `SceneError` with the rule it breaks. The methods `to_document()` and `write()` then check the whole scene, for every value the inputs can take, and report all failures at once. This second check covers the cross-references between the pieces and the rules that depend on the values of the inputs. The method `write_html` makes it as well, since it builds the document through `to_document()`. Each line of the report starts with the name of a rule from [`spec/tycho-scene.md`](https://github.com/beeson-group/tycho/blob/main/spec/tycho-scene.md), e.g. `transform-channels` or `panel`. Read the rule, fix the scene, and never work around a check by editing the document.

## How the pieces fit

- A _trajectory set_ holds trajectories that share a frame and a meaning, e.g. a family, a manifold, or one transfer. A trajectory is a sequence of samples, and a sample is one stored point of the trajectory with the numbers stored for it. The method `scene.trajectory_set(id, frame=, periodic=)` declares a set. Its method `add(positions, channels=, parameters=)` takes one trajectory as `(m, 2)` or `(m, 3)` positions, channels as one value per sample, and parameters as one number per trajectory. In these shapes `m` is the number of samples of the trajectory, and a position of two columns is planar, with `z = 0`. A channel is a quantity that changes along the trajectory, e.g. the time, and a parameter is a quantity of the whole trajectory, e.g. its period or its eccentricity. Every trajectory of a set gives the same names, because the writer stores each channel and each parameter of a set as one array over all its trajectories. With `periodic=True`, the last sample is the closing sample, one period after the first, i.e. the first sample again, reached one period later. The advance of a channel over one period is then its value at the last sample minus its value at the first, e.g. the period itself for a time channel.
- A _frame_ is a coordinate frame, e.g. the rotating frame of the restricted three-body problem or an inertial frame, declared with `scene.frame(id, parent=, origin=, rotation=, scale=)`. The frames of a scene form a tree, whose root is the one frame without a parent. A frame is defined against its parent by an origin (three numbers or attributes, or a body), a rotation about an axis, and a scale. The angle of the rotation and the scale may each read a _channel_ of the drawn sample (`ty.channel("true_anomaly")`) or an _attribute_ of the drawn set (`ty.attr("mu")`, with `1 - ty.attr("mu")` allowed), and an origin may read an attribute but not a channel (rule `origin`). The call `ty.rotation("z", angle)` gives a rotation by `angle` radians about the axis z. An attribute is one number for a whole trajectory set, given in `attrs=` of `scene.trajectory_set`, e.g. the mass ratio `mu`. An expression such as `1 - ty.attr("mu")` stands for a factor times the attribute plus an offset. One attribute thus places both the primary at `-mu` and the secondary at `1 - mu`. A set drawn in a frame must carry every channel and attribute on the path, which is rule `transform-channels`, and the writer reports which one is missing. An edge is the link from a parent frame to a child frame. The path is the chain of edges from the frame of the set to the frame in which it is drawn. Every edge on the path is evaluated with the channels of the drawn sample and the attributes of its set.
- A _body_ is a point in a frame at three numbers or attributes, declared with `scene.body(id, frame=, position=)`, e.g. the primary at `[-ty.attr("mu"), 0.0, 0.0]`. It is placed by the _reference trajectory_ of the panel, i.e. the one trajectory that the panel follows. A body does not have samples, hence it reads its channels and attributes at the current sample of the reference trajectory (rule `sample-context`). A body drawn in a frame that rotates by a channel thus moves with the samples of the reference trajectory.
- An _input_ is a value that a person viewing the page can change through a control, and a scene has three kinds of inputs. A parameter input holds a value of a parameter and selects the member of each set whose value is nearest. A member is one trajectory of a set. The built-in parameter `@index` is the number of the member in its set, starting at 0, hence `scene.parameter("k", parameter="@index")` selects a member by its number. A choice holds one of its strings, e.g. the id of a frame, and a toggle holds a boolean, e.g. whether a layer is shown. The methods `scene.parameter(id, parameter=)`, `scene.choice(id, values, scope=)`, and `scene.toggle(id)` declare them. Under the default `scope="shared"`, the page holds one value of the input. Under `scope="per_panel"`, every shown panel keeps a separate value, which is how one declared panel serves five frames. The Broucke example, for instance, shows one declared panel five times, each with a different value of a per-panel choice of frame.
- The _clock_ is the time of the animation. It is shared by every panel, so that all panels move together, and `scene.clock(mode, channels=, frame_count=)` declares it. Its `frame_count` is the number of frame indices, i.e. drawn pictures, in one loop of the animation. The first of its `channels` is the clock channel at the start, i.e. the channel whose value is read as the time, and the playback control switches among them. In `fraction` mode, one loop takes every trajectory from the first to the last value of the clock channel on the trajectory, which keeps members of different periods in phase. In `epoch` mode (`range=`), every trajectory shows the same value of the clock channel, for a common epoch. In this mode the value of the channel runs through the interval `range` over one loop, and every trajectory is shown at the point where its channel takes this value. Every clock channel is strictly monotone along each trajectory, i.e. it only increases or only decreases, so that each of its values occurs once on a trajectory (rule `monotone-clock-channel`). The channel `@index` is the stored sample index. A set drawn with a trail, a head, or a grow must carry every clock channel. A set drawn whole with `reveal="none"`, on which a reading is not taken and which does not hold a reference trajectory, does not have to carry any (rule `clock-channel-carried`). A grow is a layer with `reveal="grow"`, which draws each trajectory from its start up to the moving point. A set is drawn whole by a layer with the default `reveal="none"` and without a head.
- A `fraction` clock can run several _revolutions_ per loop, where a revolution is one traversal of a periodic trajectory from its first sample to its closing sample. The call `scene.clock("fraction", channels=[...], frame_count=480 * 9, revolutions=9)` makes one loop run every periodic trajectory 9 times, and revolution `j` is read with every channel raised by `j` periods. A channel raised by `j` periods has each of its values increased by `j` times the advance of the channel over one period. An orbit drawn in a frame that turns by the time therefore keeps turning instead of jumping back (rule `revolutions`). With a single revolution, the angle of such a frame returns to its starting value at the start of every loop. A trail fraction is then a fraction of the whole loop, and a readout reads the current revolution of the reference trajectory. The writer rejects revolutions on an `epoch` clock, and on a set that is not periodic when a trail, a head, a grow, or a reference trajectory reads this set. The reason is that only a periodic set defines what its next revolution is. In either mode, `seconds=` of `scene.clock` sets how long one loop lasts at speed 1, in place of 8 seconds a revolution.
- A _panel_ is one picture on the page, declared with `scene.panel(id, frame=, reference=, layers=, camera=)`. It combines a frame (or a choice of frames), a reference trajectory, a camera, and layers. The frame is the display frame, in which everything is drawn. The reference trajectory, given by `ty.reference(sets, member)`, is the trajectory that the animation follows, and the bodies and the readouts of the panel are placed and read at its current sample. The camera is a 2d camera, `{"kind": "2d"}`, which draws a flat picture of one coordinate plane, or a 3d camera, `{"kind": "3d"}`, which draws a three-dimensional picture that can be turned. Under a 2d camera with `"aspect": "free"`, the two axes are scaled separately for a diagram such as a residual against an iteration count, and under the default, `"equal"`, the shape of an orbit is kept. Under a 3d camera with `"stretch": [1, 1, k]`, a drawing that is nearly flat in `z` is shown `k` times taller in `z`, and this axis is titled `z ×k`. With `"auto_rotate": d`, the camera is turned by `d` degrees about the up axis over each loop of the clock. Each layer draws one thing, and the layers are `ty.trajectories(sets, members, reveal=, trail=, taper=, head=, read_from=, color=, opacity=, width=, highlight=)`, `ty.arrow(sets, vector, members, scale=, before=, after=, color=, width=, head=)`, which draws `scale` times the vector of two or three channels as an arrow at the reading, `ty.inset_box(panel, color=, opacity=, width=, dash=, min_size=)`, which draws the rectangle that the first shown panel of another declared panel with a 2d camera shows, mapped at the reading of the reference trajectory and following the pan and zoom of that shown panel, `ty.body(body, trail=, size=)`, `ty.axes(span=)`, and `ty.grid(labels=)`. The argument `sets` is a set, an id, or `ty.by_tags(family=family_choice, branch="periapsis")`, a tags query that must not match more than one set for any value of its inputs, while a query without a match leaves the layer empty (rule `set-query`). The tags of a set are the strings given in `tags=` of `scene.trajectory_set`, and a tags query matches every set whose tags contain all the pairs of the query. A value of the query may be a choice, e.g. `family_choice` above, and the query then follows the value of the choice.
- The _layer options_ set which members a layer draws and how it draws them.
  - The option `members` is `"all"`, the number of a member, a parameter input, or `ty.evenly_spaced(40)`. The call `ty.evenly_spaced(n)` is the `{"evenly_spaced": n}` reference to the members `0, s, 2s, ...` and the last member of a set of `N` trajectories, with `s = floor(N / n + 0.5)`. The call `ty.evenly_spaced(40)` thus spreads about 40 members over the set as a sparse subset, i.e. one that keeps every `s`-th trajectory, and the step is 1 when `n` is at least `N` (rule `members`). The member of a reference trajectory is never evenly spaced (rule `members`), since the reference must resolve to one trajectory.
  - The option `color=` is `"#rrggbb"` or `{"parameter": "eccentricity", "colormap": "viridis"}`. The first is a fixed color, with two hexadecimal digits each for red, green, and blue. The second is a colormap over a parameter, which gives each trajectory the color of its parameter value, and the colormap names are `viridis`, `plasma`, `cividis`, `blues`, and `reds`. The colormap can be keyed on a choice, as in `{"input": frame, "map": {"rotating": "blues", "inertial": "plasma"}}`, e.g. to give each display frame a separate colormap. The map then holds one name for every value of the choice and does not hold any other key, and the value of the shown panel picks the name (section 2.7).
  - The option `highlight={"input": e, "width": 2.5, "kernel": {"width": 0.05, "opacity": 0.55}}` draws the member that the parameter input selects. In this example `e` is a parameter input. The highlighted member is drawn with the width of the highlight in CSS pixels (by default the width of the layer) and with its opacity (by default 1). The kernel also brightens the neighbors of this member, with a Gaussian falloff in the parameter of the input, and it brings up a member at distance `d` in this parameter to opacity `max(o, a * exp(-(d / (w * extent))^2))`. In this formula, `w` and `a` are the width and the opacity of the kernel, `o` is the opacity of the layer, and `extent` is the range of the parameter over the set (section 2.7). The distance `d` is measured from the parameter value of the highlighted member, and the opacity of the layer stays the floor.
  - The options `trail=0.3, taper=(0, 0)` fade the width and the opacity from the head to `taper` times their values at the tail, and `taper` defaults to `(0.25, 0.35)`. A trail of 0.3 draws the last 0.3 of the loop behind the moving point, and a `trail` fraction implies `reveal="trail"`. The pair `taper` gives the fractions of the width and of the opacity that are left at the tail, hence `(0, 0)` fades the trail out completely.
  - The option `head=True` or `head={"color": "#f0e442", "size": 9}` draws the point at the reading, in the color of the layer, at a size that the runtime picks unless one is given (rule `head`). The point at the reading is the current position of the moving point, and the size is in CSS pixels.
  - The option `read_from="reference"` transforms every sample of the layer into the display frame with the channels and attributes of the reference trajectory at its reading, rather than of the sample itself (rule `read-from`). A grid of the rotating-pulsating frame, stored as a trajectory set without channels and drawn whole, thus breathes and turns with this frame in the rotating and inertial frames. The set of the reference trajectory must carry the channels of the frames, and the set of the grid need not carry any. Such a layer is redrawn on every frame index, and the static trajectories layers of a panel are drawn once and kept only up to the first redrawn layer, hence a large static family is best listed before it.
  - The call `ty.axes(span="full")` runs the axes both ways through the origin, `span="positive"` draws the positive halves, and `ty.grid(labels=True)` numbers the grid. Under a 2d camera, `span` and `labels` default to full and true. Only there do the axes get tick numbers and titles with the unit of the frame, e.g. `x̃ [DU]`, and only there does the grid get numbered lines that follow the camera. The title of an axis is its label from `axes=` of `scene.frame`, followed by the `unit=` of the frame, which is DU (the distance unit) in this example. Under a 3d camera, `span` and `labels` default to positive and false.
- A _shown panel_ is a declared panel on the page, with a separate value of each per-panel input. The call `scene.show("p1", panel="main", inputs={frame: "rotating"})` of the minimal scene shows the declared panel `main` as `p1`, with the choice `frame` set to `"rotating"`. The shown panels of a scene are laid out side by side in one row, unless `scene.layout` with `ty.split` arranges them otherwise. A layout that names a declared panel which was not shown shows it under its own id, and a scene without `scene.show` and without a layout shows every declared panel.
- The _controls_ bind inputs (`slider`, `tabs`, `toggle_control`) and the clock (`playback`). A control is a widget on the page that sets one input, or runs the clock.
  - The method `scene.slider(parameter_input, label=, domain=)` moves a parameter input from one parameter value to the next, over the sets that the set query `domain` matches.
  - The method `scene.tabs(choice, label=)` shows one tab per value of a choice.
  - The method `scene.toggle_control(toggle, label=)` switches a toggle.
  - The method `scene.playback()` adds play, pause, and the switch of the clock channel. A scene without it is static, i.e. it shows the initial frame index and does not animate, apart from a kiosk page written by `write_html(path, kiosk=True)`, which plays at once.
- A _readout_ is text whose parts (e.g. `{"parameter": "eccentricity", "digits": 4}`, `ty.channel("time")`, or `1 - ty.attr("mu")`) are read at the reference trajectory of the panel. The method `scene.readout(place, *parts)` adds one, with `place` either `"panel"`, for a readout in each shown panel, or `"caption"`, for one readout below the panels. A caption readout is read at the reference trajectory of the first shown panel in layout order. A string part is shown as it is, a parameter part shows a parameter of the reference trajectory, and `digits` is the number of significant digits.

## The timeline: camera moves, captions, and steps

A scene for a talk moves things by the time of the video, i.e. the timeline `s = q * L` in seconds, rather than by a stored channel (section 2.11 of the spec). Every motion is a list of _keyframes_ `(t, v)` or `(t, v, ease)`, with the eases `linear`, `smooth`, `in`, `out`, `in-out`, and `hold`, written with `ty.keyframes(...)`, and `ty.fade(on, off, duration=)` writes an opacity that rises and falls.

- The clock in epoch mode takes `keyframes=` in place of `range=`, so that the mission time pauses, speeds up, or eases (rule `clock-keyframes`). With `end="stop"` playback holds the last frame index, as a video does.
- A layer takes a layer clock, `clock=ty.layer_clock("tau", keyframes=...)`, on a channel of its set, e.g. a cloud grown backward in a backward time beside a transfer drawn whole (rule `layer-clock`). Its set carries that channel instead of the clock channels of the scene.
- A 2d camera takes `"keyframes": [ty.camera_keyframe(at, width=, center=), ty.camera_keyframe(at, width=, follow=[ty.follow(layer_index, member)], ease="smooth"), ...]` (rule `camera-keyframes`). The width is the visible extent along the first axis of the plane, the height follows from the panel unless the aspect is free, the center blends linearly and the width geometrically, and a keyframe with `follow` centers on the mean of the current points of members of trajectories layers of the same panel. A window computed by the caller, e.g. a smoothed percentile box, becomes keyframes sampled every few frame indices.
- `ty.label(text, at, offset=, align=, baseline=, size=, color=, weight=, box=, leader=, opacity=)` writes text at `ty.at_point(x, y)`, `ty.at_member(set, k)`, or `ty.at_screen(fx, fy)` (rule `label`). Its text, a readout's, or an overlay's (`scene.text(...)`, `scene.legend([ty.entry(...)], at=)`) takes the parts `ty.clock_value()`, `ty.clock_time()`, `ty.keyframed_number(*keyframes)` for a counter, and `ty.timed_text((t, text), ...)` for a caption that changes over the timeline, with `decimals=`, `grouping=`, `factor=`, and `offset=` (rule `timeline-parts`).
- `ty.points(set, marker=ty.marker(shape=, size=, color=, edge=, edge_width=), reveal="grow")` draws the stored samples as markers, appearing as the clock passes them (rule `points`). A head takes the same marker form, a `glow` while a channel is positive, and `ty.trajectories(..., line=False)` draws the heads alone. `ty.trajectories(..., opacity=0.2, group_opacity=True)` blends each pixel of a translucent layer once, as one translucent path of a plot, so a dense cloud keeps one shade.
- Opacities, marker sizes, the `opacity` of a panel, and the ratio of a split (`ty.split(..., keyframes=)`) take keyframes. The `margin` of a panel keeps a part of it free, an axes layer with `span="box"` draws the box of a plot with tick numbers, a trajectories layer takes `dash=`, `fill=`, and `color=ty.threshold_color("S", [0], [coast, thrust])`, and a body takes an `image`.
- `scene.step(id, at)` names the times a presentation stops at, and the viewer element plays to them with `playTo`, `next`, and `previous` (rule `steps`).

## Thinning

Thinning drops stored samples of a set to make the page smaller. The method `trajectory_set.thin(n, frames=[...])` keeps at most `n` stored samples per trajectory at equal steps of arclength, measured in every frame listed, and never creates a sample. Each step between two consecutive samples counts with its largest length over the listed frames. Each of these lengths is taken relative to the extent of the set in its frame, i.e. the diagonal of the box that bounds every trajectory of the set. Without `frames`, the arclength is measured in the frame of the set alone. Give it every frame the set will be drawn in, so that a flyby stays resolved where it is seen. A stretch that is short in one frame and long in another thus keeps its samples, because its long length counts.

The call `thin(tolerance=...)` runs Douglas-Peucker relative to the extent of the set, and `keep=` forces indices (e.g. thrust switches or epochs). The Douglas-Peucker algorithm adds samples until every dropped sample lies within a distance of `tolerance` times the extent from the segment between its kept neighbors, in every listed frame. The argument `keep` holds one list of indices per trajectory, or a function that returns this list for the number of a trajectory. Both endpoints of a trajectory and every forced index are always kept, even when they number more than `n`. Thin after the last `add`, since `add` raises on a set that is already thinned.

## Where the channels come from

A frame edge is the link from a parent frame to a child frame, with its origin, rotation, and scale. Take every quantity that a frame edge reads from the library that computed the trajectory, per sample, and never from a formula in the script. Every number on screen then comes from this library, because the runtime only rotates, scales, translates, and blends what it is given. In the elliptic restricted three-body problem the independent variable is the true anomaly. Name the channel for it, and store the pulsation scale `rho` and the elapsed time per sample, as [`examples/broucke/build.py`](https://github.com/beeson-group/tycho/blob/main/examples/broucke/build.py) reads them from its input. The pulsation scale is the distance between the primary and the secondary, which scales the rotating-pulsating frame into the rotating frame. The elapsed time lets the clock run uniformly in time as well as in the true anomaly. In the circular restricted three-body problem in nondimensional units, the inertial angle is the time channel. The time unit is defined so that the rotating frame turns by one radian per time unit, hence the angle between the rotating frame and an inertial frame equals the time.

## Checking a scene

In the tests, the document from `scene.to_document()` validates against [`spec/scene.schema.json`](https://github.com/beeson-group/tycho/blob/main/spec/scene.schema.json), the JSON Schema of the scene document. The function `pytycho.evaluate(document, container, state, frame_index)` returns every drawn position for a frame index, the same answer that the browser draws. Use it to assert in a test that a scene draws what it should. Its `container` is the data container, e.g. the bytes from `scene.to_container()`, and its `state` is a state of the page, e.g. `document["initial"]`, the state in which the page opens. Both evaluators, this one and the one in the browser, pass the same conformance corpus in `spec/conformance/`, which is why their answers agree. The method `write_html` returns the size of every array and of the page, in bytes as stored. Three-component positions stored as float32 cost 12 bytes a sample before compression, planar ones 8, and each channel costs 4 bytes more.
